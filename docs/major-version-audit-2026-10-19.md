# MetaFlow 12.0.0 详细审查与优化

日期：2026-10-19。维护源：仓库根目录 main；本轮开始于 2a2f3d9，并快进整合远端两条 README 提交至 5d8a413。工作记录位于独立交付目录，历史测试结果只作为定位线索，最终验证以 dist/verification.json 为准。

## 已确认并修复的问题

| 优先级 | 位置 | 问题与影响 | 修复与回归 |
| --- | --- | --- | --- |
| P1 | runner.ts、batch-map.ts | 本地规则和缓存命中主要连续推进 Promise 微任务，事件循环可能无法及时派发停止和重绘；原准备队列仅每 64 个完成条目让步，单条耗时不受预算约束 | 共用 8 ms／64 次检查点的调度器；规则准备、条目派发和逐规则执行都检查，让步后重新检查取消和队列边界；测试原生定时停止、已完成变更保存及有界并发 |
| P1 | hooks.ts、core-workflow.ts、workflow-result.ts | 卸载只停止规则队列，未显式取消并等待核心工作流的期刊预热及最终汇总；可能在持久化刷新后继续收尾 | 同时取消活动核心任务和规则执行，等待两个队列排空后再刷新运行文件；测试收尾顺序及失败队列排空 |
| P1 | journal-ranking-index.ts | 更高格式版本索引被跳过读取后，旧版在新查询时仍可能以旧格式重写原文件 | 更高版本文件进入只读保护，允许本次会话使用新查询结果；测试原对象及写入次数保持不变 |
| P2 | reporter.ts、report-view.ts | 一次创建全部条目 DOM，报告较大时打开和操作成本随条目数增长；缺少筛选定位 | 搜索索引、条目级严重度／变更筛选、每页 25 张卡片；完整导出保持原数据；纯逻辑及原生窗口测试翻页、筛选、字段详情和完整导出 |
| P2 | http.ts | then 的成功处理器抛错不进入同一次 then 的拒绝处理器；已标记完成且无过期时间的条目可能长期复用拒绝 Promise | 在成功处理之后统一 catch，按实例身份移除失败缓存；测试首次处理异常后第二次网络查询成功 |
| P2 | reporter.ts | 条目链接无键盘语义；异步修复动作可连续重复点击 | 使用原生按钮跳转条目，动作执行期间禁用并在结束后恢复 |

## 边界与后续值得投入的项目

- 8 ms 是检查点之间的协作预算，不是可抢占式实时保证；单个复杂同步规则仍可能超过预算。
- 分页限制条目卡片数量，不限制单条目的证据行数；完整导出仍需序列化全部结果。大量附件／超长字段的内存与导出压力值得另测。
- 第三方服务的实时账户权限、限流变化和全量响应组合未由受控回归证明。
- macOS／Linux、全部第三方插件共存以及超大资料库长期运行不在本机验证范围。
- 本次按用户要求提升主版本号；没有为了版本号引入不兼容数据迁移或新偏好。

完整日志和静态设置清单保存在本轮独立工作目录；正式交付只记录必要的审查文档、源码、生产包及可核对的验证清单。
