# 功能与数据布局统筹

适用于正式版 `11.2.1`；版本验收见[发布说明](releases/metaflow-v11.2.1.md)，此前候选证据及商业发行边界见[审查台账](commercial-readiness-2026-10-18.md)。

## 用户工作流

| 入口 | 主要职责 | 可选耗时能力 | 交互原则 |
| --- | --- | --- | --- |
| 自动导入 | 按已启用选项完成导入元数据补全、本地检查及重复条目策略 | 导入补全、自动去重由各自设置决定 | 使用独立导入开关，避免与手动命令绑定 |
| 检查并修复元数据 | 默认本地检查与格式修复 | 联网核验、作者核验、期刊信息、重复文献处理 | 核验和作者合并查询，身份判据通过后直接填充 |
| 更新元数据 | 从数据源更新文献，并按选项修复格式 | 版本演进、期刊信息、重复文献处理 | 更新模式为补空或覆盖；保留预印本并关联正式版本 |
| 设置中的工具中心 | 低频、单独执行的专项工具 | 用户主动选择 | 精简右键菜单仍保留两个核心命令 |

PDF 标识符扫描和无标识符标题检索默认关闭，统一由补充检索选项控制。自动填充无需差异审阅面板或确认窗口。重复文献的实际合并保留明确决策，支持一次处理多个重复组。

### 元数据来源优先级

设置中的“元数据来源优先级”统一原有补空／覆盖选项，沿用同一偏好值，默认本地优先，不增加第二套互相冲突的开关。两个核心命令已启用的联网元数据步骤及单独核验工具遵循同一选择，运行开始后保持本次选择；此设置不会自动启用联网步骤。

- **优先本地数据**：保留已有书目字段，来源数据仅补空；已有作者名单是否补全，仍遵循作者补全开关。
- **优先云端数据**：在身份核验通过后采用来源已有字段，来源空值不清除本地内容。对明确 DOI 查询，本地、请求与返回 DOI 完全一致时，可按此选择更新存在标题、年份或作者差异的字段，并记录 `metadata-cloud-priority`；作者禁用字段仍不写入。
- 不同 DOI、核验失败、仅凭标题或 PDF 线索的匹配仍执行原有保护。预印本关联正式版继续执行版本关系校验，不用云端优先绕过。自动导入仍采用独立的补空策略。缩写来源、评级数据源优先级使用其原有设置。

标题身份比较统一 HTML 下标与带空白的 MathML 公式表示，避免将 WSe₂／WS₂ 的表示差异误判为不同文献；比较不改写本地标题。

## 完整命令的调度、反馈与记录

1. 核心命令先去除重复选中项，再按执行顺序进入核心命令队列。相同命令、相同条目集合的连续点击复用同一个任务；不同核心命令等待前一完整流程结束。
2. 每次执行开始时读取阶段开关、更新方式、补充检索和本地规则列表。同一次执行的这些选项保持一致。
3. 各阶段继续通过既有 runner 队列保存文献及执行原生合并。自动导入和专项工具也使用 runner；核心命令队列没有把整套 Zotero 操作锁成一个数据库事务。
4. 右下角原生通知显示命令和阶段，不再向文献列表底部添加横条。运行中可以停止后续执行；停止信号只绑定本命令取得 runner 后的操作，并跳过后续阶段，不会取消无关的导入或专项任务。已完成保存不会自动回滚，无法取消的宿主调用可能仍需等待返回。
5. 阶段结束后按条目 ID 合并结果，保存、失败和修改条数不因多个阶段重复累计。重复处理涉及选中范围外条目时纳入总数；任一阶段失败不会被后续成功覆盖。字段变更按阶段顺序保留。
6. 主界面与设置页使用同一个最终结果。命令结束后移除运行状态条，在右下角显示 Zotero 原生样式的完成通知，5 秒后自动消失，鼠标悬停不延长时间。点击通知或使用键盘激活后查看本次报告；后续任务不会替换该通知对应的报告内容。连续完成的通知只保留最新一条，历史记录继续保存在日志中。元数据流程不弹确认窗口。
7. 每个核心命令只持久化一条 `core-check` 或 `core-update` 摘要，阶段不各自重复写历史。普通规则批次及独立工具仍记录自己的执行。

原始各阶段结果保留在当前会话的 `lastCoreWorkflow.stages`；`runner.lastResult` 是合并后的完整命令结果。条目是否保存、失败、适用及处理状态由 runner 和原生重复处理提供，无需为了汇总重新读取全库。

## 设置布局

设置按使用频率及任务排列：自动导入与后台处理 → 右键菜单与核心功能 → 元数据来源与采纳偏好 → 去重 → 期刊评级、索引与数据源 → 期刊名称缩写 → 详细元数据规则 → 数据、缓存与运行反馈 → 按需工具、快捷键、富文本及关于。通知、并发和诊断集中在数据区；自动导入总开关关闭时，相关子选项禁用但保留已保存选择。完整审查见[设置体验审查](settings-experience-audit-2026-10-19.md)。

常规和核心功能默认展开。详细规则默认折叠，仍可按字段分类配置；所有原有偏好键继续保留。缓存、运行记录和上次报告归入“数据、缓存与运行反馈”，避免在元数据服务和常规设置中分散维护入口。

## 数据所有权与读取路径

| 数据 | 权威位置 | 读取方式及维护 |
| --- | --- | --- |
| 文献、作者、关系、附件 | Zotero 文献库和附件目录 | 由 Zotero 保存；插件缓存不能替代文库备份 |
| 功能开关、服务凭据、非重复判定 | Zotero 偏好设置 | 保留现有 `extensions.zotero.metaref` 命名空间；缓存键使用凭据摘要，运行摘要不记录凭据 |
| 内置缩写、ESI、Nature Index 数据 | 插件打包的数据资源 | 懒加载、索引复用；明确重载或版本更换时更新 |
| 联网响应 | 配置目录 `metaflow-api-cache-v1.json` | 内存共享请求，再读取持久缓存，最后联网；按服务区分期限和容量 |
| 已保存的期刊评级 | 配置目录 `metaflow-journal-rankings-v1.json` | 作为已保存结果回退，区别于仍在有效期的联网响应 |
| 运行摘要 | 配置目录 `metaflow-runtime-data-v1.json` 及 `.bak` | 最多 30 天、200 次、2 MiB；每次最多 50 个条目摘要 |
| 详细字段变更、可点击报告 | 当前插件会话 | 不复制到运行摘要；需要完整内容时由用户主动导出报告 |

清理接口缓存不会删除文献、设置、已保存评级或运行摘要。运行文件不是撤销日志，也不是数据库备份。完整的期限、字节限制和损坏恢复策略见[缓存与存储策略](automatic-metadata-and-runtime-cache.md)。

## 效率与验收边界

本次新增结果归并仅线性遍历条目和证据，不额外全库扫描。期刊信息后续预取按题名、ISSN 和期刊缩写组合去重，最多 4 个并发任务；请求层继续复用响应和在途请求。

验收覆盖实际设置绑定、重复点击、跨核心命令排队、取消、前序结果保留、单次历史记录、缓存和批量合并。双宿主结果与安装包校验见仓库 `dist/verification.json`。在线服务使用受控响应；未覆盖所有真实账户、操作系统和超大文库长时间压力场景。不据此宣称完全兼容或无缺陷。


候选版的内部批量去重使用代表连接保留候选和可合并分组，避免密集组生成全部两两组合。供体每次合并前重新对照已审阅快照；检索期间已消失的条目跳过。元数据准备最多四路并发，明确标识符按批共享在途和失败结果，标题译者因携带完整上下文按条目隔离。作者补全开关控制导入和元数据填充；主动启用的“检查时联网核验作者”和本地作者格式规则按各自开关执行。
