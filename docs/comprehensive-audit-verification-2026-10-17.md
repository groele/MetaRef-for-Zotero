## 摘要中另外两项判断

- HTTP：`requestHTTP` 对 429/503 最多重试一次；支持 Retry-After 秒数与日期。超过 5 秒的服务端退避会直接报告，避免规则占用线程过久；不是完全没有退避。Semantic Scholar 无 key 每 3 秒限速、有 key 每秒限速。是否需要跨批次延迟队列属于产品取舍，不能把服务限流一概当作客户端算法错误。
- 内存：内置数据懒加载、跨批复用；DataLoader 有 clearBatchCache/clearCache，索引重载和卸载也有清理。原报告未提供 50 MB 堆快照或“无释放”的证据。频繁清空内置索引反而增加后续加载与重建成本。本次不依据该结论删除缓存。

## 现代化迁移建议的边界

报告建议全面将 XUL 迁移为 Web Components，但未列出具体弃用 API 或失效控件。当前设置页已有宿主适配与实际点击回归；这些测试不能代表未来所有 Zotero 11 构建，却也不支持“现有控件必须整体重写”的结论。后续应按已弃用接口或可复现失效逐项迁移，保留现有可用的设置与生命周期清理。

## 代码工作链条

1. Bootstrap 加载 Gecko 沙箱，index/addon 建立共享实例；hooks 注册菜单、列、侧栏、偏好与通知。
2. 自动新增格式化只选启用的标准规则；工具类入口显式调用，不会混入自动流程。prepare 为一次批次准备选项；取消或失败隔离。
3. LintRunner 串行排队批次，以有界 worker 处理条目；单条目按规则注册顺序执行。规则具有截止时间和中止信号。
4. 异步读取前记录字段身份；返回时验证用户是否修改过目标/标识字段。MutationJournal 捕捉规则写入，在失败时只撤销仍属于该规则的值。
5. 全部规则后统一保存；事务失败恢复待保存快照并逐条重试；成功保存值、失败记录和报告分别统计。warning 是核对提示，不再把“发现重复”算作规则执行失败。
6. 期刊数据链：设置总权限 → 启用字段 → EasyScholar 响应/本地 ESI、Nature 索引 → 标准化 → 允许写入的 Extra → 列与侧栏。二级列设置只决定入口位置，不能突破总权限。
7. 侧栏普通渲染只读；点击导航按缺失字段触发补全，正在更新去重、完成后短期抑制。显式更新仍走原入口，不被导航抑制阻止。
8. API 调用有缓存、同请求共享、限速、超时和取消；没有把每次显示列变成网络查询。Nature 自定义数据集解析继续沿用此前真实响应核验的 UUID 与等级格式。

## 外部规范核对

- [Better BibTeX Extra 文档](https://retorque.re/zotero-better-bibtex/exporting/extra-fields/)说明 Extra 标签映射与 tex 专用字段的不同。不能仅凭“非标准字段存在”判断解析崩溃或乱码。
- [Zotero 富文本说明](https://www.zotero.org/support/kb/rich_text_bibliography)描述支持字段中的类 HTML 标记。该说明主要针对标题，不能外推为所有姓名导出器的兼容保证；也不支持原报告所写的必然编译错误。
