# 10.4.0 工程说明与验收范围

## 手动入口

“检查并修复元数据”执行已启用的规则。开启作者远程修复且启用作者检查时，会增加作者查询；不开启完整元数据流程时仅修复作者，不覆盖一般字段。开启完整元数据流程时仍以补空策略组合检查规则。

“更新元数据”按设置中的仅补空/覆盖模式查询文章信息，默认同时查询期刊信息。作者修复有独立开关：开启时即使一般字段为仅补空，也允许修正已有作者；关闭后作者按一般补空/覆盖策略处理。自动新增条目的元数据流程保持仅补空。

## 侧栏导航图标

触发点是 Zotero 原生 `item-pane-sidenav` 中该插件的导航图标。监听器按文档安装并在销毁时移除，通过该导航栏当前容器定位条目。缺少选中的期刊输出字段、ESI 学科或明确的 Nature Index 结果时执行补全。普通条目选择、面板正文和渲染流程不会发起网络请求。

同一条目只允许一个补全任务；批处理统一保存并刷新侧栏及列表列。处理中切换条目不会将结果渲染到另一条目。未被 API 返回的字段不编造；再次点击可以重试，但有效响应会命中缓存。API/本地来源优先级继续生效，本地查询不需要 API 密钥。

## 72 小时缓存

新成功响应从实际查询完成开始计时。EasyScholar 期刊名仅在缓存键中进行 Unicode、空白和大小写规范化；发送的查询保留原名称。Semantic Scholar 的论文 ID、DOI、arXiv 和 PubMed 别名共享同一响应体与到期时间，重启后仍可复用。

配置目录下继续使用 `metaflow-api-cache-v1.json` 文件名，内部 schema 升级到 2，并兼容读取 schema 1。旧缓存不延长期限。最多保留 1024 个响应/别名条目；缓存文件不保存明文请求 URL 或密钥。响应体本身包含查询得到的文献信息。写入有 500 毫秒合并延迟，异常退出可能丢失尚未落盘的最后一批缓存，但不会影响已经保存的条目元数据。

缓存不是永久存档：过期、清除、容量淘汰、更换密钥、变更查询标识或字段配置需要时允许重新请求。连接测试刻意绕过结果缓存。网络和业务错误不作为成功结果缓存；合法的未收录结果可以复用。

## 审查边界

10.3.0 审查中的 F1/F2/F4 缓存问题和 F3 自定义缩写歧义问题已有正式回归覆盖。F6 由本次主线发布交付处理。F5 中“已保存 ESI 字段”和“按来源优先级解析的 ESI 学科”仍保留各自的展示/列语义，未将两者强行视为同一数据。

不能将受控响应测试等同于真实账户对所有服务、字段和数据年份的在线验收；也不能据一次 Zotero 11 开发版验证保证所有后续版本。历史审查报告保留当时状态，以本次发布的 `dist/verification.json` 为交付验证记录。
