# 12.5.3 CI layout-contract follow-up

The first cloud CI run completed 197 native tests successfully and failed one shortcut-layout assertion: the native row was 56.8 CSS px high while the test required at most 52 px.

The layout test and preferences CSS are identical between the preceding 12.5.2 source base (83b5b8e) and the 12.5.3 release commit (19e3efe). This failure does not identify a new runtime-layout regression in the cancellation patch.

The follow-up changes only the E2E layout contract. It retains the no-overflow, grouped-buttons and contained-actions assertions, and replaces the platform-specific absolute height ceiling with explicit one/two/three-track responsive structure, valid resolved dimensions, font-relative compact spacing, measured content-fit and no vertical clipping. An empty disabled-shortcut preview may collapse; control tracks must remain visible. It does not shrink text, alter settings CSS, skip tests or change the published XPI. Native controls and system fonts are allowed to determine their intrinsic height.

The first structural-test attempt sampled unresolved native layout (`gridTemplateRows: none`). An isolated Windows Zotero 10.0.6 diagnostic confirmed this transitional state, then measured settled 570/470/350px layouts with one/two/three tracks. The test now waits for fonts and bounded, resolved native layout instead of assuming 100ms is sufficient. This is a readiness condition, not a skipped assertion or an increased pixel ceiling.

The immutable v12.5.3 annotated tag and its published assets remain unchanged. A subsequent main-branch CI run validates this test-only follow-up independently.
