# Zotero MetaFlow 10.3.0：期刊来源、缩写与查询缓存

## 完成提示

普通成功提示在处理完成后停留约 **1.5 秒**，不需要鼠标移入即可自动关闭。警告保留 4 秒，失败保留 6 秒，取消保留 2.5 秒，方便阅读。完成后点击提示只关闭提示，不再发起停止请求。详细结果仍可从设置中查看最近一次运行记录。

## ESI 与自然指数来源

在“期刊索引与自定义数据库”中分别选择 ESI、自然指数的来源策略：

| 策略 | 行为 |
| --- | --- |
| API 优先 | 查询 EasyScholar；没有可用结果时使用本地库 |
| 本地优先 | 本地命中时无需联网，否则查询 API |
| 仅 API | 只采用 API 数据，未返回时显示未知 |
| 仅本地 | 使用自定义文件和内置库，保持离线；默认选项 |

手动运行查询才按策略请求 API。选中文献、显示“Zotero MetaFlow 期刊索引”和条目列只读取已保存数据、有效内存缓存或本地库。重启后的磁盘缓存会在下一次显式查询时加载，此时有效命中不发送网络请求。

ESI 只接受能识别为 ESI 学科的数据，不将 JCR 分区等同于 ESI 学科。自然指数从 EasyScholar 返回的具名自定义数据集识别，也可以填写该数据集 UUID。API 明确返回“否”与未返回数据有不同含义。索引面板显示来源与数据集名称，应核对 82 种、145 种等目录版本；API 权限和数据集是否启用取决于用户账户。本次回归使用受控响应，未使用用户真实密钥验证账户权限。

## 独立的“期刊名称缩写”折叠面板

沿用 journalabbr 的自定义映射、内置映射、ISO 4 推断工作流，整合到已有缩写规则中，避免增加重复执行入口。

- 来源：自动、自定义文件、内置映射、离线 ISO 4。
- 自动顺序：自定义 CSV/JSON → JabRef → 离线推断（需启用推断）。
- 数据源偏好：综合库或 18 个来源分表，包括 IEEE、ACS、AMS、NCBI Entrez 等。选择分表时，分表优先，综合库补充未命中项。
- 匹配：默认保留标点区分的标准刊名匹配；可选宽松匹配，出现冲突时跳过并提示。
- 已有值：可靠映射可校正、仅填空白、允许推断替换。默认在未命中可靠映射时保留已有手工缩写。
- 格式：句点保留/去除、保留大小写/大写/小写/词首大写/按词首字母。按首字母属于用户格式转换，不代表标准期刊缩写。
- 来源标签：可选维护 `abbr`、`abbr_user`、`abbr-iso4`，不影响其他标签，默认关闭。
- 保留自定义路径、无匹配时以全称填充、中英文控制。会议缩写仍使用原有会议数据与规则。

JabRef 数据版本为 `d2532fb80c72d0940d1715d13b7830696e3b4253`：综合库 **44,304** 个刊名、**18** 个来源分表。生成器保留标点差异，按显式来源优先级去重；来源差异与文件校验值写入 `journal-abbr-provenance.json`，可重复生成。不同来源存在历史名称和期刊自定格式差异，不能保证每个条目都符合特定出版社的最新要求。

ISO 4 推断使用本地 LTWA 2021 和 AbbrevIso 引擎，不请求网络；推断结果应与期刊官方缩写核对。JabRef CC0、AbbrevIso MIT 与上游来源说明随包附带。插件作者为 `groele`，原项目及第三方版权声明保留。

本次整合范围为刊名缩写及其控制项，不声明移植 journalabbr 的所有独立工具（例如 BibTeX 导出工具）。

来源：[zotero-journalabbr](https://github.com/zoushucai/zotero-journalabbr)、[JabRef Abbreviation Lists](https://github.com/JabRef/abbrv.jabref.org)、[AbbrevIso](https://github.com/marcinwrochna/abbrevIso)。

## 两层缓存及重新请求条件

1. **条目数据**：分区、影响因子等所选字段保存到条目的 Extra；索引面板读取这些已保存值，显示信息无需重新查询。ESI/自然指数来源查询采用只读索引展示，不覆盖档案、系列等无关字段。
2. **请求响应**：EasyScholar 与 Semantic Scholar 成功响应在当前配置目录缓存 6 小时，内存中合并相同请求的并发调用；磁盘文件为 `metaflow-api-cache-v1.json`，重启后仍可复用。

缓存按服务、查询及凭据隔离。磁盘只保存成功响应、到期时间和哈希索引，不保存请求 URL 或明文密钥；响应本身包含查询到的学术元数据。缓存数量有上限，容量淘汰后允许重新请求。重载缓存不延长原有有效期；网络错误和逻辑错误不缓存。

Semantic Scholar 的标识符查询与元数据查询请求同一组所需字段，在当前会话中通过 DOI/论文 ID 别名复用响应。任意不同查询路径未能归并为同一标识符时，仍可能分别请求；不能把不同用户凭据、所有检索条件或不同服务强行视为同一请求。

以下情况会重新联网：缓存过期或被淘汰、查询条件/密钥改变、设置中主动清除 API 查询缓存、未命中可用响应。**测试连接始终直接联网**，便于检验当前密钥是否有效。清除缓存不会删除文献中已写入的信息；文件损坏或读写失败时继续执行正常查询。

EasyScholar 提供期刊分区、指标、收录等期刊层级数据；Semantic Scholar 提供题名、摘要、DOI、发表信息等论文层级数据，两者按各自用途缓存，不相互替代。
