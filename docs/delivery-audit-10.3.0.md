## 已复现问题

### F1：同刊大小写变体可能重复请求 EasyScholar

位置：`src/utils/easyscholar.ts:328`、`:337`、`:366`；`src/utils/http.ts:37`。

并发查询 `Nature` 与 `NATURE`，受控 HTTP 计数为 **2**，目标是 1。解析缓存键已转小写，但两个调用在缓存尚未生成时均继续执行，底层请求键又包含保留原大小写的 URL，导致没有合并。

建议：在解析层按规范化刊名、凭据及数据集建立进行中的 Promise 索引；查询共享结果，在此之后才处理实际网络限速。不要用删除刊名标点的方式强行归并不同期刊。

### F2：Semantic Scholar 标识符别名未跨重启复用

位置：`src/modules/rules/tool-update-metadata/services/semantic-scholar-service.ts:7`、`:17`、`:31`。

先按 DOI 取得论文响应并写入磁盘，再重载模块模拟新会话，改用返回的论文 ID 查询。响应未过期，但受控 HTTP 总计为 **2**。原因是响应已持久保存，DOI/论文 ID 别名映射仍只在内存中。

相同 DOI 重查的已有缓存用例可以通过；问题集中于跨会话切换标识符的情形。这一边界此前说明文档已经保留，本轮将其转为明确的失败验收用例。

建议：为受信响应建立凭据隔离的持久别名索引，别名到期时间沿用原响应，清缓存时一起删除；覆盖 DOI、论文 ID 和实际需要的其他标识符。

### F3：严格匹配的自定义缩写库仍使用宽松键冲突校验

位置：`src/modules/rules/require-abbr.ts:274`。

自定义库同时包含 `A-B Journal → AB. J.` 和 `A B Journal → A. B. J.` 时，加载报 `Conflicting abbreviations for A B Journal`。两个名称本可按当前默认严格匹配区分，却在载入阶段被 `normalizeKey` 合并。内置映射的精确/歧义处理已经分离，自定义加载器尚未同步。

建议：精确键仅拒绝真正相同刊名的冲突；宽松键另行标记歧义，宽松查询时跳过，不拒绝整个有效文件。保留 CSV/JSON 与文件激活校验的同一套规则。

### F4：同刊并发虽共用 HTTP 响应，仍逐个经过限速队列

位置：`src/utils/easyscholar.ts:337`、`:366`；`src/modules/menu.ts:158`。

10 个完全相同刊名同时查询，受控 HTTP 为 1 次，但使用真实节流器、虚拟计时器记录的完成时间为：

```text
0, 500, 1000, 1500, 2000, 2500, 3000, 3500, 4000, 4500 ms
```

缓存命中的消费者仍排队，批量同刊查询会被无意义延迟。这里是受控请求与虚拟时钟复现，不是远程服务器耗时测量。

建议：与 F1 合并修复；仅对实际出站请求限速，共享进行中的查询和已完成缓存均直接返回。加入 10 个/大量同刊条目的批次耗时验收。

### F5：ESI 展示和列尚未完全归并

`src/modules/journal-pane.ts:125` 从 Extra 生成含 ESI 的评级列表，`:154` 又渲染独立的 ESI 学科结果。`src/modules/item-tree.ts:35` 注册 ESI 学科列，`:65` 还可注册 EasyScholar 的 ESI 列。

两个位置有不同保存/来源语义，但用户要求相似功能合并，因此需要明确一个主展示值及来源优先级，将保存值、当前解析值和来源差异放入可展开说明；迁移列偏好时保留兼容性。本项是源码确认，未声称本轮已通过实际截图复现所有冲突组合。
