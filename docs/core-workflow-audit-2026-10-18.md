# MetaFlow 设置分区、核心覆盖与执行冲突专项审计

本报告对应本地候选版 `10.7.0-beta.2`，维护目录为 `.scaffold/publish/metaflow-10.0.1`。沿用原有设置键与用户偏好；未发布、未安装到主用户资料库。

## 1. 结论

两个菜单能够覆盖日常的校验、格式整理、文献核验、作者补全、arXiv 版本管理、期刊指标及重复核对。此前确有步骤遗漏、开关含义不一致、报告覆盖和不必要的完整快照开销，本轮已修正。参数型编辑及破坏性维护仍保留在按需工具中。

这不等于把全部 58 个注册规则／工具每次都执行一遍。39 项常规规则直接进入本地检查；另一项长 DOI 规则的能力由联网核验按需解析承接，原开关保留在高级兼容选项中。18 项工具中，7 项日常能力已进入两个核心流程或其可选步骤；另外 11 项需要参数、选区或独立确认，保留单独执行。

不能称为“与三个原扩展完美兼容”。本轮验证的是 MetaFlow 内部吸收三组能力后的实现，不依赖同时安装 ZotMeta、DOI Manager、arXiv Workflow 或 Zoplicate；没有完成这些原插件所有版本同时启用时的组合测试。

## 2. 设置分区

| 顺序 | 分区 | 负责的设置 | 与其他区的边界 |
| --- | --- | --- | --- |
| 1 | 常规设置 | 自动导入总开关、群组、延迟、格式任务并发、通知、最近报告 | 自动导入使用独立设置，不继承手动命令的可选联网步骤 |
| 2 | 两个核心功能与耗时选项 | 检查与更新分别选择阶段、格式模块总开关、补充检索 | 管“何时执行”；详细规则和来源仍在对应专门区域 |
| 3 | 元数据规则 | 具体规则、适用字段、词典及格式偏好 | 格式模块总开关与这些规则共用原设置键，没有第二套相互覆盖的值 |
| 4 | 期刊名称缩写 | 数据来源、匹配、推断、输出格式及自定义文件 | 继续使用单独卡片，执行受期刊／会议规则与格式模块控制 |
| 5 | 元数据来源与采纳偏好 | 字段补空／覆盖预选、作者采纳、服务凭据、缓存、高级兼容规则 | 管“从哪里取、怎样采纳”，不重复放置流程启用开关 |
| 6 | 去重设置 | 默认处理、主条目、并发组数、类型、统计、非重复记录、批量控制 | 导入处理与手动交互核对分开；不把全库批量合并放入每次核心操作 |
| 7 | 按需工具 | 参数型编辑与维护工具 | 不因菜单隐藏或模块勾选而自动执行 |
| 8–11 | 右键菜单、快捷键、富文本、关于 | 入口位置、按键、选区编辑及版本信息 | 入口配置不改变规则是否启用；精简菜单保留原位置偏好 |

修正了分区重排后“期刊名称缩写”被遗留在全部设置最顶部的问题。常规设置和核心流程现在位于前两位。菜单的精简开关移入右键菜单区，按需工具独立成区；联网作者开关和更新时的期刊开关只在核心流程中显示一次。

## 3. 两个核心命令的实际执行顺序

### 检查并修复元数据

1. 可选书目核验；没有启用完整核验时，可单独选择作者核验。
2. 执行已经启用的本地检查与格式规则。
3. 可选期刊分区、评级、ESI／Nature Index 查询。
4. 可选交互式重复核对；启用时替代第 2 步中的普通重复提醒扫描。

默认只有第 2 步。一般 DOI 缺项检查只报告缺项，不暗中联网查找。完整书目核验和作者核验同时开启时只查询一次；明确开启作者核验的选择优先于一般的作者采纳关闭偏好。

### 更新元数据

1. 可选联网书目核验和逐字段采纳，默认开启。
2. 可选本地格式整理，默认开启；复用已启用规则，不重复补全作者、查询 DOI 或扫描重复。
3. 可选期刊指标，沿用原有 `metadata.updateJournalInfo` 偏好。即使书目信息没有变化，或用户关闭第 1 步，也可以独立执行。
4. 可选交互式重复核对，默认关闭。

核对界面取消会停止后续步骤；各阶段已经保存的结果不会自动回滚。最近批次报告保留本次所有批处理阶段的字段变化和提示，不再只保留最后一个格式或指标批次。独立去重的决策结果仍由其原有结果提示展示。启用更新后的本地格式整理时，通常不需要再单独点击一次检查；没有变化的字段不会重复保存。

菜单、检查快捷键和设置页中的常规更新入口使用同一编排。旧版直接规则调用保留其原有语义，以兼容已有调用者；独立高级核验与版本工具仍可完整执行。

## 4. 耗时功能的选择与限制

| 功能 | 开关位置与默认行为 | 成本与控制 |
| --- | --- | --- |
| 完整书目核验 | 检查默认关闭；更新默认开启 | 联网；字段差异仍须确认 |
| 单独作者核验 | 检查默认关闭 | 完整核验已开启时不再额外查询；只做作者核验时不采纳其他字段 |
| arXiv 正式版查询 | 更新流程中的独立选项，默认关闭 | 只查询明确关联的出版 DOI；预印本本身的元数据核验仍可使用 arXiv，不会因此推断出版关系 |
| PDF 候选扫描 | 补充检索中独立选项，默认关闭 | 仅在条目没有现成标识符时读取已有 PDF 缓存；每份最多 32 KB，必须人工选择，不上传 PDF |
| 标题查询 | 补充检索中独立选项，默认关闭 | 仅在没有标识符／所选 PDF 候选时查询，仍验证题名和年份；不是无条件第二遍搜索 |
| 期刊指标 | 两个命令各有独立开关；检查默认关闭，更新保留原偏好 | 尊重字段选择、数据源优先级及缓存；同一阶段不再另加独立 ESI 和 Nature 查询规则 |
| 重复提醒 | 本地详细规则中的原开关 | 可对大文库关闭；没有第二套提醒开关 |
| 交互去重 | 两个命令分别选择，默认关闭 | 只围绕当前所选条目找候选；检查时替代普通重复扫描，更新格式阶段不扫描重复 |
| 全库批量合并、统计刷新 | 去重设置页中按需操作 | 不夹带进两个菜单；暂停／停止等待已开始的提交完成 |

关闭书目核验时，版本选项会禁用；两个命令均不需要联网核验时，补充检索选项禁用并保留原值。无效的去重并发值不保存。

## 5. 已找到并修正的问题

| 问题 | 修正 | 对应验证 |
| --- | --- | --- |
| 核心更新后没有格式整理步骤 | 新增独立可选阶段，复用本地规则，默认开启 | 原生测试验证先核对后去除标题末尾句点 |
| 期刊刷新只处理书目信息发生变化的条目 | 指标改为独立阶段 | 原生测试覆盖书目核验关闭及书目完全未变两种情况，第二次请求复用缓存 |
| 检查中的联网补全与更新入口走不同采纳逻辑 | 产品入口统一使用逐字段核验 | 原生对话框采纳、取消、身份与快照验证 |
| 完整补全和作者开关可能重复或相互抵消 | 合并为单一核验阶段，明确作者选项优先级 | 同时开启及重复点击，只产生一次转换器查询，作者仍可采纳 |
| 重复点击对同一批条目重复排队 | 同类命令、同一组条目复用进行中的任务 | 原生并发两次调用，验证查询次数为 1 |
| 交互去重与普通重复提醒重复扫描 | 交互核对替代提醒阶段；更新格式不扫描重复 | 调度与规则过滤核对，重复相关原生回归 |
| 大库去重先序列化所有条目的完整元数据 | 先比较 DOI、标题、年份、首位作者等必要字段，仅对命中候选生成完整快照 | 原生测试令无关条目完整序列化抛错，候选检索仍成功；命中候选保留完整快照 |
| PDF、标题与正式版查询没有独立开关 | 新增默认关闭的补充步骤 | 原生测试分别覆盖关闭无查询、开启后候选选择、标题采纳和版本开关 |
| `bookTitle`／`proceedingsTitle` 被大小写敏感匹配漏分 | 按规则 ID 小写归类 | 单元测试与设置页模块联动测试 |
| 长 DOI 联网规则显示为本地组合规则 | 移至来源区高级兼容卡片，排除本地模块总开关 | 静态设置扫描、原生控件持久化及默认离线验证 |
| 后续阶段覆盖前序报告 | 保留组合流程的各阶段结果并在设置页统一查看 | 原生测试断言格式结束后仍保留前序日期采纳证据 |
| 移动复选框时留下原标签，导致重复 ID 和标签指向错位 | 整体移动选项容器及说明，不再只移动输入框 | 完整原生回归检查全部设置 ID 和偏好绑定唯一性 |

格式并发与去重并发是两个不同参数：前者每批 1–16 个条目，后者每批 1–8 个互不重叠的重复组。二者通过同一执行队列协调，没有相乘到 128 个同时写入的任务。原生合并拥有自己的事务，不能再套一层插件事务。组合流程按阶段保存，不宣称整条流程为一个原子事务。

## 6. 覆盖范围与保留的独立功能

| 类别 | 两个核心命令的覆盖方式 |
| --- | --- |
| 常规检查与格式 | 39 项规则直接复用；长 DOI 在联网核验中按需处理。包含标题、短标题、作者格式、语言、期刊／会议、缩写、日期、卷期页、学位论文、高校地点、书籍／专利字段及 Extra 顺序 |
| 已整合的 7 项日常工具能力 | `tool-update-metadata`、`tool-review-metadata`、`tool-review-preprint`、`tool-update-easyscholar`、`tool-query-esi`、`tool-query-nature-index`、`tool-review-duplicates`；后几项复用同一指标／核对阶段，并非重复调用所有工具 |
| 保留独立的 11 项工具 | 标题引号、作者标注、指定语言、生成 ShortDOI、CSL 编辑、Extra 清理、作者风格指定、作者姓名交换、标题替换、期刊替换、全部清空 Extra。均需要参数、选区或独立确认，不放入每次检查／更新 |
| 其他界面与数据功能 | 数据导入导出、非重复判定迁移、列显示、富文本选区、缓存清理、连接测试和目录入口不是文献处理阶段，继续由对应设置或工具触发 |

## 7. 三组整合能力的兼容结论

| 能力来源 | 已整合及验证范围 | 不能据此宣称的范围 |
| --- | --- | --- |
| ZotMeta + DOI Manager | 标识符候选、ShortDOI 解析、身份核验、字段差异与补全；统一保存边界、过期快照阻止写入 | 不是原插件全部功能的逐行移植；没有验证每一种真实服务响应与账号权限 |
| arXiv Workflow | 明确关联 DOI、预印本与正式版差异、原位更新或创建关联条目、附件与笔记保留 | 不包含自动 PDF 版本替换或所有预印本平台；核心流程的正式版查询现在需明确开启 |
| Zoplicate | 设置页五类设置、主条目决策、逐字段选择、非重复记录迁移、有界批量合并与统计 | 未进行所有原插件版本同时安装的矩阵；大型文库长时暂停／停止压力测试尚未完成 |

原插件如果同时启用相同的导入自动补全或自动合并，可能分别处理同一条目；MetaFlow 的队列不能调度其他插件内部的任务。要验证这种共存，需要指定原插件版本及自动处理配置，不能把孤立宿主测试写成共存测试。吸收能力后的 MetaFlow 自身不要求这些原插件作为运行依赖。

## 8. 最终验证

最终通过 74 个测试文件中的 485 项单元测试；Windows Zotero 10.0.6／Gecko 140 和 Zotero 11.0-dev.5+dac1ad489／Gecko 153 各通过 131 项完整实机测试，均包含生产 XPI 安装验证。新增的 10 项核心流程场景已纳入两套完整回归。构建、TypeScript、ESLint、AutoCorrect 和差异空白检查通过。静态扫描核对 286 项默认设置和 124 个静态绑定，无缺失、重复或无法解析的绑定；实际设置页的控件 ID 与可见偏好绑定唯一性亦通过原生断言。

40 条文献的受控场景中，Zotero 10 本地校验为 172 ms、0 次请求；显式 DOI 查询为 2,043 ms、40 次请求，模拟服务延迟为 15 ms。该结果验证了离线路径没有隐式网络调用，不是现实服务上的固定加速比例。两个宿主分别保存了性能复测 JSON。XPI SHA-256、完整日志和限制见交付目录 `verification.json` 及 `verification/`；设置总览截图来自实际 Zotero 10 测试窗口。

外部响应使用受控测试数据，不能证明实时在线服务始终可用。Zotero 11 范围限定为所测开发版。原插件共存、macOS／Linux 及大文库长时压力测试未完成。前一轮报告的测试结果没有用于替代本轮验证。
