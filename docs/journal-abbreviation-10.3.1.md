# Zotero MetaFlow 10.3.1：期刊缩写整合修复

本版本完成期刊缩写模块中的自定义匹配缺陷修复，并核验它与内置映射、ISO 4、会议缩写及设置的协作流程。作者保持 groele，插件身份和既有偏好保持连续。

## 修复内容

| 问题 | 10.3.1 行为 |
| --- | --- |
| A-B Journal 和 A B Journal 被当作文件冲突 | 分别建立精确键，两条均可载入并写入各自缩写 |
| 宽松键冲突影响整个文件 | 文件可用；只有无法唯一判断的宽松查询跳过并提示，原值保留 |
| 自定义和内置库使用不同匹配逻辑 | 统一使用同一个精确/宽松双索引与歧义判定器 |
| 真正相同刊名对应不同缩写 | 大小写、空白和 Unicode NFKC 规范化后检测冲突，在设置激活前拒绝文件 |
| CSV 重复行 | 完全相同的映射去重，设置中的条数按唯一精确刊名计算 |
| CSV 分隔符识别受引号内逗号干扰 | 第一条逻辑记录中只统计引号外分隔符，支持转义双引号、BOM 和换行 |
| 未选择文件却启用仅自定义来源 | 显示明确提示，保持原值 |
| 仅内置来源仍报告未使用的自定义文件错误 | 期刊规则忽略未选择来源的文件错误 |
| 已有正确来源标签反复删加 | 只移除过时的管理标签；正确标签不动，重复处理无变化时不保存 |

## 处理顺序

1. 先遵守“已有缩写处理”：仅填空白时跳过非空值。
2. 按所选来源检查自定义精确映射；宽松模式才尝试宽松键。
3. 查询存在歧义时给出警告并结束，不继续使用低优先级猜测替换。
4. 自动模式下，自定义未命中后查询所选 JabRef 来源；分表优先，综合库补充。
5. 自动模式下两类映射均未命中且启用推断时，使用本地 LTWA/ISO 4；非空手工值需要显式允许替换才参与推断。
6. 再遵守中英文全称填充、大小写、句点及来源标签选项，统一交给 runner 保存。

自定义文件与期刊规则共用同一套校验，避免“设置能激活，运行时又换一种匹配”的差异。会议缩写仍支持自定义映射、去除届次后匹配以及原有会议库；遇到自定义歧义时也不会任意选择一项。

## 数据及设置

独立“期刊名称缩写”折叠面板保留：4 种来源模式、综合库与 18 个来源分表、精确/宽松匹配、3 种已有值策略、5 种大小写样式、句点、来源标签、自定义路径、ISO 4 推断和全称填充。

本地 JabRef 数据仍为 44,304 个刊名映射，版本 `d2532fb80c72d0940d1715d13b7830696e3b4253`；许可与来源记录随包保留。ISO 4 推断离线执行。映射库及推断不能代替投稿前核对期刊要求，也不宣称逐刊人工核验。

## 范围说明

本次整合是 journalabbr 的期刊缩写工作流、数据源与相应控制。期刊名交换、通用正则/函数替换及 BibTeX/CSV 导出属于独立工具，不计入本次期刊缩写修复的完成范围。

用户允许正常刷新并覆盖已有缓存；该偏好与“是否替换用户手工填写的文献缩写”是两个不同控制，本模块按明确的已有值策略执行。
