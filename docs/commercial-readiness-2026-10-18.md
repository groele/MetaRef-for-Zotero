# 商用发布质量审查与验收台账

基线：正式版 11.1.0（主分支 `3c744e6`）。本轮逐链路审查，修复后先验收当前项目，再推进下一项。旧版的 519 项单元、175 项 CI 原生、双 Windows 宿主各 61 项安装包检查作为基线；不将旧结果计作新版本全部通过。

## 对话要求与验收原则

- 保留 Zotero MetaFlow 品牌及两个核心右键命令；显示开关与执行步骤同区管理。
- 自动导入有独立开关；低频、联网及耗时步骤可选，避免重复查询、重复扫描和重复保存。
- 元数据按身份判据直接填充，不弹确认窗口或差异审阅面板；无法确认的身份保留原值。
- 去重支持多组批量处理；保留明确合并决策、暂停／继续／停止，以及 Zotero 原生数据保留能力。
- 版本演进保留预印本，关联正式出版版本；遵守作者开关并拒绝过期快照。
- 缓存分层、定期淘汰、限制条数和字节；运行摘要独立保存，避免泄露字段原文或密钥。
- 设置需验证实际执行效果，而不只验证控件可点击；兼顾键盘、窗口关闭与多窗口生命周期。
- 退役冗余入口，保留历史发行版；稳定更新源、安装包与标签一致。
- 用故障注入和规模数据确认稳定性及效率；不重复审查未变化的已验收链路。

## 已确认问题

| ID | 级别 | 证据及影响 | 处置 |
| --- | --- | --- | --- |
| MF-01 | P1 | 核心状态条直接调用共享 `runner.cancel()`。核心阶段排队等待导入／专项任务时，点击停止可能取消当前其他任务，却不能阻止自身排队阶段稍后执行 | 增加任务所属的取消信号；仅当前任务取得 runner 后才绑定取消 |
| MF-02 | P1 | 期刊规则保存完成后才刷新列与侧栏，阶段结果在整个函数返回后才归档；刷新抛错会丢失已保存阶段的结果并终止后续步骤 | 隔离展示故障，保留原始保存结果与可追溯警告 |
| MF-03 | P2 | 日志依赖主窗口 console；窗口不可用时错误日志自身抛错，可进一步打断收尾和反馈 | 宿主日志先写入，窗口控制台仅作可选展示 |
| MF-04 | P1 | 同批次同 DOI 复用候选时沿用了首条目的 `identifier`；首条为明确 DOI、后条为 PDF 摘录时，后条可能绕过摘录所需的独立证据检查 | 只共享远端响应，按每条目的当前标识符来源和快照重新绑定判据 |
| MF-05 | P2 | 相同 DOI 查询失败后未加入批内复用；三条相同 DOI 在同批次重复请求三次 | 批内共享在途及失败结果；下一次命令重新请求，不写入持久失败缓存 |
| MF-06 | P1 | 自动导入使用另一套填充路径，未传入作者策略；旧直接规则在覆盖模式下也未禁止关闭的作者修改 | 导入使用同一核验链路；直接规则明确尊重禁用作者选项 |
| MF-07 | P2 | 准备阶段串行、每次应用使用数组 `find` 定位；本地缺少任何独立证据时仍进行注定无法应用的标题检索 | 受控并发最多四路、批内请求合并、按条目索引应用，并在本地提前跳过无证据检索 |
| MF-08 | P3 | PDF 选项仍写“需要人工选择”，与已移除的确认界面矛盾 | 中英文说明改为自动证据核验 |

01 的新增取消回归在修复前有 3 项失败，修复后通过；新增关闭窗口日志回归在修复前有 2 项失败。调度、规则回滚及生命周期定向单元 35 项通过；Zotero 10 中包含排队停止与保存后界面故障的原生 24 项通过。最终包仍须在全链路修改结束后做双宿主安装验证。

02 的原生回归复现了 PDF 证据升级、失败请求三次重复及无证据标题仍联网；自动导入旧路径还进入不必要的服务回退并超时。修复后的 9 项定向原生检查通过，包括共享失败结果后新命令重试、导入／覆盖模式作者开关、准备并发上限以及逐条标识符结果。全体单元测试此阶段为 530 项、82 文件通过。

10,000 条选择结果定位的 Node 微基准：旧数组扫描三次为 38.1、24.1、22.6 毫秒；索引读取为 0.55、0.37、0.29 毫秒。该基准不含网络、建索引和 Zotero 保存，不等同于插件整体加速。

商用成熟度以该台账的实际结果和剩余风险评估，不以测试数量、版本号或单次构建替代。

03：原生 21 项定向检查通过；5,000 条同 DOI 的内部批量候选为 4,999 条（原全对组合为 12,497,500 条）。150 组固定种子随机数据比较了排除关系、选择子集、文献类型与 arXiv 版本下的全部候选和可合并连通分组，结果一致。公开全对 API 保留，内部批量／统计使用双生成森林；极端不兼容或大量排除关系仍可能需要二次方比较，但逐步让出事件循环，候选存储不再按全部两两组合增长。

MF-09（P2）：密集重复组全对枚举和保存，导致候选内存二次方增长。内部改为保留候选／可合并分组的代表连接，主条目选择改为单次遍历。
MF-10（P1）：批量组开始之后的用户修改会被后续新快照接纳。每个供体提交前重新对照审阅快照；已完成合并保留，剩余修改条目停止处理。另修正组部分失败时将已保存条目再次标记为失败的统计。
MF-11（P2）：检索期间消失的条目可导致整个检索抛错。跳过消失／回收站条目，并按完整当前快照复核匹配。

04:25 项缓存／策略单元及 18 项原生检查通过。新增门控写入与清空的竞态检查：清空排在在途写入之后，主／备份均为空，之后新记录正常保留。现有损坏恢复、磁盘失败重试、未来格式保护、独立关闭屏障和密钥不落盘检查通过。未发现需要新增缓存层或缩短保存期的证据，避免无益重构。现有上限：公共请求 5 分钟／128 条／4 MiB；服务内存 512 条／16 MiB；服务持久化 1,024 条／8 MiB；期刊 72 小时、论文 24 小时、空期刊 5 分钟；运行摘要 30 天／200 次／2 MiB，最多 50 条条目摘要，不存标题／字段值／错误原文。

MF-12（P2）：设置仍展示只作用于旧直接 API 的类型变更开关，并错误声称影响导入；核心命令已按保留预印本和关联出版版本执行。移除无效界面入口及过时说明，底层偏好保留以维持直接 API 连续性。


06：生产依赖 `pnpm audit --prod --json` 当前报告 0 个已知漏洞（9 个普通依赖及 8 个可选依赖）；这不是没有漏洞的证明。项目许可原先仅存在源码根目录，现构建时同步进入 XPI 的 licenses 目录，并在安装后实际读取核对。构建更新清单加入 XPI 校验散列；本轮不覆盖稳定更新源。

商用发布门槛仍包括：ESI／Nature Index 打包数据的商业再分发许可依据尚未在仓库中确证（见 `index-data-2026-09-30.md` 的原始记录）；需要权利来源核查或替换为授权数据。现有 AGPL 源码与第三方许可保持。文档中残留“修改预印本类型”“写 Nature Index 标签”“数据仅批内缓存”等旧描述已按当前路径修正。未将本轮技术测试解读为许可审查结论。

MF-13（P2）：标题译者接收完整条目上下文；不同年份／作者的同名条目不能共享首条核验失败结果。标题检索按条目隔离；明确标识符仍在批内共享。新增同标题不同年份的原生回归通过。

全量首轮 183 通过、3 失败，定向定位为：导入作者修复关闭后，缺失作者检查正确报错（旧测试依赖不遵守开关的行为，现显式启用并验证作者写入）；取消旧测试要求停止后继续晚写（改为验证阻止晚写且保留先前已完成规则）；新增许可测试用普通文件接口读 jar 资源（改为 Gecko 资源接口）。未降低产品身份、取消或保存判据以通过测试。

2026-10-18 重新读取官方来源：[Nature Index brief guide](https://www.nature.com/nature-index/brief-guide) 明示近 12 月数据采用 CC BY-NC-SA 4.0；[ESI scope](https://essentialscienceindicators.zendesk.com/hc/en-gb/articles/28150642413201-Scope-and-Coverage) 提供期刊清单，但该页没有说明打包副本的商业再分发许可。以上不能替代对本项目具体清单提取物的权利认定，正式商业分发前仍须解决。

全量第二轮 186 通过、1 失败；失败是新增的等待供体修改测试假设最后创建条目永远是供体。实际详细优先策略和条目 ID 分配可让它成为主条目。测试已改为原生首轮合并结束后取得实际仍未合并的供体，避免错误测试身份。产品供体快照复核逻辑不放宽。

补充校验：构建时保留生产更新清单，生产 XPI 安装测试通过 Gecko SHA-512 实际计算包散列并与清单比较，避免仅检查字段存在。稳定下载清单和包仍保持 11.1.0。作者说明明确元数据作者开关与主动启用的作者专项核验／本地作者格式规则的职责。


## 功能归属与成本边界

| 能力 | 自动导入 | 检查并修复 | 更新元数据 | 独立维护 |
| --- | --- | --- | --- | --- |
| 本地格式／必填检查 | 总开关及各规则控制 | 默认执行启用规则 | 默认启用格式阶段，可关闭 | 单项规则 |
| 身份核验与书目补全 | 独立启用，仅补空 | 可选，默认关闭，仅补空 | 默认执行，补空／覆盖可选 | 专项 API 保留 |
| 作者来源核验 | 遵守作者补全开关 | 书目核验包含作者，或显式单独核验；不重复请求 | 遵守作者补全开关 | 本地姓名规则独立 |
| PDF 及标题回退 | 不扫 PDF；标题需已有年份／作者 | 可选，默认关闭 | 可选，默认关闭 | 身份证据不足不请求／不采纳 |
| arXiv 正式版本 | 不自动创建 | 不承担版本创建 | 可选，保留预印本并关联正式版 | 既有版本工具 |
| 期刊评级 | 独立导入选项 | 可选，默认关闭 | 独立阶段可关闭 | 查询、侧栏、列各有显示权限 |
| 重复文献 | 默认保留全部，可显式配置自动策略 | 可选，默认关闭 | 可选，默认关闭 | 全库批量、非重复判定导入／导出 |
| 清空 Extra、批量替换等维护 | 不执行 | 不执行 | 不执行 | 用户主动执行 |
| 运行摘要／缓存维护 | 后台合并写入 | 每个完整命令一条摘要 | 每个完整命令一条摘要 | 清空／重载／导出按需 |

作者补全关闭不禁用用户主动选择的作者专项核验或本地格式规则；说明已区分这三个职责。两个核心命令涵盖日常整理、更新、期刊及去重流程，破坏性维护和低频配置保留在设置工具中心。
