# Zotero MetaFlow 功能与可靠性逐项验收

本轮候选版本：10.7.0-beta.4。源码维护目录为 `.scaffold/publish/metaflow-10.0.1`。本报告补充本轮发现、修复和验收证据；既有功能分工见 `core-workflow-audit-2026-10-18.md`，上一轮去重记录继承说明见 `integration-hardening-2026-10-18.md`。

## 1. 结论与审查规则

三组扩展的主要能力已进入 MetaFlow 自身的设置、调度和保存体系，但前一版仍存在设置联动、关联条目采纳、失败恢复和结果反馈的缺口，因此此前不能称为完美整合。本轮按功能建立验收项，修复确认的问题，并区分控件绑定、功能行为、跨版本验证和未覆盖边界。

同一功能的源文件未变化且已有证据仍适用时，保留证据，不重新展开同一审查。只有修复涉及的功能及其直接调用链进行定向复测。源码哈希对比已确认 runner、duplicates、duplicate-batch、non-duplicates、duplicate-policy、menu、shortcuts 七个文件与上一轮验收版本相同。hooks 的集合选择分支因本轮发现的 Zotero 11 API 变化单独修正和验证；自动导入分支没有修改。新增去重暂停测试用于补覆盖缺口，不是再次修改去重算法。

“验收通过”指本报告明列的场景和宿主，不表示任意设置组合、任意第三方插件版本、任意网络或文库规模均得到证明。

## 2. 本轮问题与修正

| 级别 | 问题及影响 | 修正与验证方式 |
| --- | --- | --- |
| P1 | 通用设置依赖处理会覆盖专用控件的 disabled 状态，使正式版查询、补充检索、字段列开关的灰显规则失效 | 通用逻辑仅管理存在对应父开关的控件；原生测试关闭／开启书目核验及期刊字段，并发送无关设置事件，验证状态仍正确 |
| P1 | 作者差异被开关隐藏后，创建关联正式版仍可能从候选数据复制未展示的作者 | 在核验提案中记录排除字段；关联创建优先保留原条目对应字段。原生测试确认对话框没有作者选项，正式版也没有偷偷采用远端作者 |
| P1 | 关联创建在等待数据库事务进入期间，缺少最后一次快照核验 | 在事务内及新正式版首次保存后重新检查源条目，写入前阻止过期提案；原生竞争编辑测试验证拒绝写入且保留未保存编辑 |
| P1 | 关联保存失败时重载所有字段，可能丢掉本功能未修改的手工编辑 | 跟踪是否已开始修改关系；只恢复相应条目的主数据和关系，不重载 itemData、creators。原生故障注入验证关系回滚、手工 Extra 保留且保持未保存状态、数据库没有残留正式版 |
| P1 | Zotero 11 移除单库／单集合选择 API，去重设置页的批量操作与统计刷新、旧集合命令会在执行前失败 | 新增统一选择适配，优先使用复数 API，仅旧宿主回退；多文库选择不擅自确定范围。新增单元与原生测试验证新 API、移除桩不被调用、旧宿主兼容、集合范围与多库拒绝；导入后统计刷新使用明确选中的库 |
| P2 | 创建／复用正式版的结果只弹提示，没有完整进入组合报告 | 增补关联成功记录、已保存关系变化、失败计数和取消状态；核对最终报告与条目状态 |
| P2 | 单独启用交互去重时，组合流程可能没有结果；取消也未返回给编排器 | 去重返回结构化批次结果，保留决定、异常和取消状态；原生测试覆盖仅去重阶段及取消，仅修改排除记录时不虚报条目保存 |
| P2 | 去重统计显示开关缺少可靠的即时重绘通知 | 设置修改调用宿主的立即重绘接口；原生观察者验证通知确实到达。读取当前安装 Zotero 的 notifier 实现确认普通事件在事务期间可能排队，不再用延长等待代替修正 |
| P2 | 原条目已有正式出版 DOI 时，版本迁移可能把它误标为“预印本 DOI” | 不归档仍保持不变的正式 DOI；变化的历史 DOI 使用准确的前 DOI／arXiv 预印本 DOI 标签。原生类型迁移测试验证来源记录 |

审计脚本也修正了对核心流程内部 `pref()` 读取包装器的识别，避免把七个实际生效的设置误报为未找到消费者。枚举控件的测试选择器改为实际使用的 `data-abbr-option`、`data-index-policy` 绑定；这些选择器修正不属于新增产品功能。

## 3. 设置面板逐项核对

本轮清单覆盖 286 项默认偏好；静态 XHTML 有 124 个绑定。实际页面导出 268 个设置绑定，其中 237 个是复选框，另含数值、文本、凭据、模式组及七个缩写／指标源下拉框。静态数量与实际数量不同，原因是页面在运行时生成控件。

| 设置区 | 生效路径与验证 |
| --- | --- |
| 一般与自动导入 | 主开关、群组范围、通知、报告、并发由 hooks／runner 读取；延迟后重新检查主开关。原生自动导入、规则保存、停止及并发用例验证实际行为 |
| 两个核心功能 | 检查和更新分别生成执行计划；作者核验与完整核验不重复请求；书目关闭后可单独更新指标。PDF、标题和正式版查询分别可选；原生开关、请求计数、字段结果及取消验证 |
| 本地规则 | 原开关直接决定启用的标准规则；顶部聚合开关修改同一组原偏好，混合状态可见。原生实际点击与规则注册表断言验证，不保留第二套相互矛盾的开关 |
| 期刊缩写 | 来源、数据配置、匹配方式、已有值策略、大小写分别保存；所有七个缩写／指标源下拉框的全部枚举值通过实际事件保存检查，行为由缩写与数据源原生测试验证 |
| 元数据采纳 | 补空／覆盖、作者差异、自动补全与高级兼容选项分工保持明确。核心流程仍经逐字段确认；类型迁移只出现在明确的版本流程，旧类型开关保留给自动／旧版调用 |
| 期刊字段、列及数据源 | 字段开关控制取值和写入；列开关受字段及对应主开关约束。已有原生用例验证列注册、显示值、数值排序、来源优先级和自定义数据库加载 |
| 去重 | 四类默认动作、四类主条目策略、并发、跨类型、统计和导入导出分别读取。原生设置、批量合并、排除继承、导入竞争写入及暂停／继续／停止验证 |
| 菜单、快捷键、富文本 | 菜单可见性与放置位置分工；快捷键校验冲突、禁用与恢复；富文本处理实际编辑器选区。复用本轮全库回归及未改动源码哈希证据 |
| 维护操作 | 自定义文件在验证后激活，取消不改路径，失效数据退回内置；连接测试防止重复请求并脱敏。原生文件选择、错误文件、重载与请求验证 |

237 个复选框通过保存事件逐一验证；既有测试另验证可用控件的真实点击与标准规则执行关联。绑定测试证明事件和偏好连接正确，不等同于穷举所有业务组合。七个下拉框之外，菜单位置、元数据模式、去重策略使用各自的原生测试。

268 个绑定没有发现缺失默认值、重复设置键或无法定位消费者。其余 18 项默认值已分类：三个去重自定义控件、非重复记录数据、一个迁移标记、一个高级导入延迟、三个菜单位置偏好，以及九个历史兼容值。九个历史值包括 cleanExtra、旧静默模式和七个工具启用值；它们不是当前页面的失效开关，旧工具启用值也不是当前工具执行条件。

## 4. 功能链路验收账本

| 顺序 | 模块 | 验收覆盖与保存边界 |
| --- | --- | --- |
| 1 | 设置面板 | 绑定、全部缩写／指标源枚举、灰显依赖、数值校验、凭据、文件、重复初始化、标签与布局；结果进入独立控件清单 |
| 2 | 元数据核验补全 | DOI／ISBN／PMID／PMCID／arXiv 候选、返回身份约束、冲突确认、作者开关、补空／覆盖、过期快照、取消；规则内修改，runner 统一保存 |
| 3 | arXiv 版本管理 | 明确出版 DOI、原位迁移、来源留存、附件笔记保留、关联创建与复用、歧义拒绝、事务进入前后核验、失败回滚和报告；关联写入独立事务 |
| 4 | 去重决策与批量执行 | 同库候选、跨类型限制、主条目策略、字段来源选择、排除继承、导入竞争写入、失败恢复、暂停／继续／停止；原生 merge 自有事务，不能外套插件事务 |
| 5 | 调度与数据保护 | 同类重复点击合并、批次排队、有界条目／组并发、规则超时、取消、单项失败隔离、保存失败恢复、手工编辑保留；复用现有 runner 审计和本轮回归 |
| 6 | 自动导入 | 通知合并、延迟、关闭后不继续、只补空、类型保护、本地校验及可选指标／去重；自动导入使用独立设置，不隐式复用人工核对步骤 |
| 7 | 指标与本地数据 | 请求去重、源优先级、字段／列权限、JSON／CSV 校验、缓存重载、失效回退；复用未改动逻辑及已有文件级原生验证 |
| 8 | 界面、生命周期及兼容 | 两个默认菜单、旧 API 兼容、快捷键、选择区工具、启动／关闭清理、生产 XPI 安装、两种宿主；不把插件依赖声明误当作原插件共存证明 |

每一项的异常、取消或未适用结果都应可追溯。字段修改以实际保存记录为准；仅改变排除偏好不计为条目保存，建立关联则记录关系字段变化。组合流程按阶段提交，取消不撤销此前已经保存的阶段。

### 最终验收证据

单元测试：75 个文件、490 项通过。修改涉及的设置 17 项、核心编排 15 项、核验与版本 17 项、去重 11 项、选择兼容 3 项，加上宿主启动与生产安装 3 项，共 66 个原生场景已在 Windows Zotero 10.0.6 / Gecko 140 和 Zotero 11.0-dev.5+dac1ad489 / Gecko 153 分批验收通过。

这里的 66 项是按功能合并的覆盖范围，不是声称最后一次测试一次运行了 66 项。两套历史全量日志曾各有 145 项通过、1 项失败；选择器遗漏、统计重绘及 Zotero 11 选择接口问题随后分别修正。最终采用受影响模块的定向验证：Zotero 10 的设置模块 17 项通过；两宿主去重／选择／安装各 17 项通过；此前组合模块中的其余场景在原生报告中均通过。相应失败日志与最终复测日志同时保留，未用当前版本去重跑没有受影响的全库测试。

静态与实际设置清单没有缺失默认值、重复绑定或未定位消费者。构建、TypeScript、ESLint、AutoCorrect 和差异空白检查通过。交付 XPI 为最后一次 Zotero 10 生产包安装测试所用文件。未安装到主用户配置，未发布或推送。

## 5. 性能与重复执行检查

保持两个默认菜单，没有增加常驻菜单或自动全库扫描。完整核验与作者核验共用一次提案；同命令同条目集合复用进行中的任务；格式阶段避免和交互去重重复扫描。普通规则处理与合并操作共享队列，条目并发和重复组并发不叠乘。

PDF 扫描、标题查询、正式版查询和交互去重默认不进入每次更新；全库合并、统计重算和记录导入导出按需执行。PDF 只读每份附件缓存前 32 KB；候选最多 20 项，不上传 PDF。批量规则限时并可取消；公共 HTTP 有超时及有限重试，元数据转换也有等待边界。

40 条受控文献的 Windows Zotero 10 测量：本地校验 181 ms、0 次请求；显式 DOI 查询 2,165 ms、40 次请求，模拟延迟 15 ms。该数据验证离线路径没有隐式联网，不代表真实服务下的固定加速倍数。最新 Zotero 11 测量与机器可读记录一并交付。

## 6. 尚不能宣称完美的边界

- 未进行 ZotMeta、DOI Manager、arXiv Workflow、Zoplicate 各版本同时安装、同时自动处理的完整共存矩阵。MetaFlow 不能调度其他插件内部队列；本轮的竞争写入测试属于受控竞态测试。
- Zotero 11 范围限定为实际测试的开发版，Windows 之外的宿主没有验证。
- 在线响应使用受控数据，不能证明每个服务当前可用、每种账户权限和全部真实异常响应都兼容。
- 去重暂停／继续／停止已有真实事务验证，但三组条目的确定性测试不等于超大文库长期压力测试；极端重复桶的候选数量仍可能较大。
- arXiv 支持明确出版关联及条目级版本处理，没有新增自动替换 PDF、完整版本时间线或所有预印本平台的统一版本系统。
- 排除记录通过本地偏好和人工 JSON 迁移；原生合并与偏好文件不是跨存储原子事务，没有新增一键撤销合并能力。

这些边界须保留在验收结论中，不能用测试总数代替。没有发现新的已暴露控件无消费者问题；已确认的数据与逻辑缺陷已在本轮修正，最终验证结果以交付目录的 `verification.json` 为准。
