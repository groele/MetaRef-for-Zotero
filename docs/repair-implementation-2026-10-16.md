# Zotero MetaFlow 工程修复记录

日期：2026-10-16。基于同日的 [实现审查](plugin-audit-2026-10-16.md) 逐阶段实施。本记录描述修复阶段，原审查的缺陷复现与历史失败日志保留。

修复工作以 10.0.0 代码为基线，保留插件名称、ID、内部资源和设置空间；不重写已有显式用户设置，不迁移日常资料库。修复阶段先保留旧发布包；随后按本记录验证结果构建并发布了 10.0.1，发布包验收信息见 [发布验证记录](../dist/verification.json) 和 [10.0.1 发布说明](releases/v10.0.1.md)。

工作开始时已有多项未提交与未跟踪内容；本轮保存了源码现状备份、原始 Git diff 和文件散列，再定向修改。备份目录：`.scaffold/repair-2026-10-16/`，其中 `source-baseline.zip` 是修改前的源码快照。

修复阶段的本地验收包位于 `artifacts/repair-2026-10-16/zotero-metaflow-repaired.xpi`，当时内部版本为 10.0.0。该包仅作修复过程记录；最终发布使用重新构建的 10.0.1 包。

## 2. 分阶段实施

### 阶段一：修复会改错数据的规则

先增加缺陷回归测试：四个文件中出现五项预期失败，再修改实现。

| 问题 | 实现 | 验证 |
| --- | --- | --- |
| M01 合法数字范围误改 | 去零函数仅移除前导零，删除将 `0-` 替换成 `1-` 的推断 | 保留 10、20、100 结尾的范围及零起点；检查幂等性；真实保存后 reload |
| M02 字段启发式误删 | 字段误用只报告疑似问题；空值清理使用数字／标识符字段白名单 | 保留 Q1、数值档案号、中文短标题、None／无等正文文字 |
| M03 人工短标题被覆盖 | require-short-title 遇到非空短标题直接保留 | 单测与实机保存验证；仍能补充空短标题 |

这不是把所有自动规则改为只读：明确的格式整理仍按启用规则运行。独立短标题大小写规则也保留其原有开关。

### 阶段二：建立规则失败恢复边界

新增 `src/utils/item-mutation-journal.ts`：

1. 通过规则代理捕获实际写操作，记录其影响字段的前值与后值。
2. 规则成功才形成变更记录。
3. 抛错、超时或报告 error 时恢复本规则的写入，不丢弃此前健康规则的结果。
4. 若字段已经被外部再次修改，恢复时保留该外部值；变更记录也不把它归到本规则。
5. 若恢复本身失败，停止该条目的后续执行和保存，尝试重新载入数据库状态；其他条目继续。
6. 规则代理禁止直接保存、删除或重新载入，避免绕过统一提交边界；规则结束后的写回仍被拒绝。

对标题、条目类型、作者列表、卷期和健康前后规则做了真实数据库验证。原有批次事务失败后逐条重试、整批撤销与重做继续保留。

### 阶段三：联网更新的身份、完整度和覆盖保护

新增纯逻辑策略模块 `tool-update-metadata/policy.ts`，由实际工具流程调用：

1. 规范化 DOI；矛盾 DOI 无条件拒绝，不因标题相似而覆盖。
2. 区分精确标识符、直接 URL 查询与普通元数据搜索；后者要求较强标题匹配及兼容年份。
3. 保留已由预印本服务查得的关联正式 DOI；正式文献已有 DOI 不被标识符补充阶段任意替换。
4. 仅回显 DOI 的响应不算完成。信息不全时尝试后续来源，按较早可信来源优先、后续只补缺项的方式合并。
5. 记录字段来源；核心信息仍不完整时报告缺项。
6. 等待服务期间被用户或其他插件修改的字段保留当前值。
7. 类型变更会丢失已有字段或改变作者角色时保留原类型。
8. 不机械拆分 Semantic Scholar 的全名作者；结构化作者仍经过角色校验。

更新菜单现在只执行更新工具，不隐式串接标准规则。新默认值为 blank；用户已有 all 等显式偏好继续生效。需要整理时使用相邻的“检查并修复元数据”命令。

身份检查降低误配风险，但不是对外部数据库内容正确性的保证。本轮没有通过实时外部服务证明全部候选都正确。

### 阶段四：取消、请求生命周期与节流

- 准备上下文加入 AbortSignal；取消可释放等待队列，关闭对应工具窗口。标准规则准备默认限时 60 秒；交互工具不强制倒计时。
- 保留原有应用阶段取消语义：不启动后续规则／条目，已开始规则结束后保存健康结果。
- 网络请求默认限时 15 秒，并连接 Gecko 请求取消回调。
- Semantic Scholar 对无匹配的 400／404 继续尝试下一个标识符，循环内同样遵守间隔；取消和其他错误不被当作无匹配吞掉。
- 429／503 按短 Retry-After 退避重试一次；服务要求等待超过 5 秒时不提前重试。
- 服务调度器按调用时的配置读取间隔，Token 变化不再需要重启才能影响调度；保留上一次请求起点。
- 公共 DOI／缩写请求共享进行中的请求，缓存有 128 项上限和 5 分钟期限；失败不保留，鉴权请求不进入公共缓存。
- 单个订阅者取消不影响其他订阅者，最后一个订阅者取消才终止底层请求。

Zotero 转换器等未提供可用取消接口的底层操作仍可能继续，晚到写回由规则代理拦截。

### 阶段五：交互、报告与原生菜单

- 标题没有选区时不插入空格式标签；窗口清理同时移除标题选区监听。
- 结果保留字段前后值、规则、可用的来源及实际保存状态；窗口可展开查看并导出 JSON。
- 导出取消不写文件；失败显示重试提示；按钮忙碌期间禁用。
- 汇总区分已保存、未变化、不适用及提醒数量；保存失败不标记为已提交。
- 报告规则名和主要工具对话框、缺作者、DOI 提示补全中英文本地化。
- 原生菜单回归改为操作实际 menupopup，等待 popupshown 与关闭状态，避免依赖隐藏父菜单后遗留的 open 属性。完整回归保留连续三轮索引查询，未跳过原失败用例。

首次修复阶段全量仍是 53 通过、1 失败；菜单组合定位后，10 项组合通过，随后完整回归通过。没有删除首次失败证据。

### 阶段六：缓存与质量门禁

- 自定义标题术语在准备阶段编译正则并复用，重置 lastIndex，避免全局正则跨条目泄漏状态。
- Extra 排序使用预计算字段集合，避免比较器内重复扫描全部字段名。
- 内置期刊／会议索引遇到冲突正规化键不再静默取某个冲突缩写；自定义缩写冲突在激活前拒绝。
- 索引菜单复用已加载数据；文件变化通过设置页“重新读取”激活，避免每次查询清空全部内置缓存。
- 单测覆盖率范围扩展到全部 `src/**/*.ts`，排除测试文件；覆盖率不再仅统计顶层规则。
- E2E 脚本拒绝单文件 entries 和空目录，并检查实际通过数，防止“0 passed”被当作成功。
- 清除 README 的已知 AutoCorrect 错误；发布工作流同时识别大小写 v/V 标签，但本轮未触发发布。

## 4. 边界与后续设计

- Zotero 11 只代表实际测试的开发构建，不能推及未来所有版本。
- 本轮不包含日常环境持久安装后的重启、多平台、所有第三方插件组合或实时外部 API 可用性验收。
- 全局“只检查／预览后应用”、大报告分页、超大批次分段提交、全库重复检测失效缓存属于后续产品／架构设计，未作为本轮缺陷修复实现；不能由现有测试推断这些功能已经存在。
- 性能用例记录的是受控场景。字段修改日记会带来开销，本轮以数据正确性优先；新旧单次耗时不能代替同负载统计或完整联网批次的性能结论。
